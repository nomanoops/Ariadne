# Work Orientation

Use this reference after Prior Knowledge Reconstruction when deciding whether a major philosophical work—or a work-part with its own method or architecture—needs a distinct work-level orientation before its first Passage Package. Its purpose is **work-level orientation**: establish, in a limited and source-grounded way, why this work appears now, which coordinates the current learning objective actually needs, and what remains to be tested in primary reading. It is neither a new research phase nor an Agent lecture, and not a mandatory preliminary course.

## Orientation has three distinct operations

Do not collapse the following operations:

1. **Orientation Diagnostic** — elicit what the learner can currently retrieve, distinguish recall from speculation, and identify possible coordinates. A response before reading new material normally establishes only *diagnostic readiness*. It may show that no new reading is needed only when the learner's existing knowledge is reliable, its source basis can be checked, and it already covers the objective-relative coordinates below.
2. **Work-Level Orientation** — choose and ground the small set of work-level coordinates required by the learning objective, the learner's current level, and the work's relevant features. The coordinates may concern a problem field, historical pressure, method, architecture, or form.
3. **Orientation Exit** — verify that the learner can reconstruct the selected coordinates, identify their source/provenance, and distinguish established coordinates from still-unverified interpretive hypotheses. Repeating an Agent hint is not source-grounded reconstruction.

The sequence is normally `Diagnostic → Work-Level Orientation → Exit → Passage Package`. A diagnostic is not an exit. Agent-side location of a candidate passage is not a learner-facing assignment.

## Trigger gate

Run Work Orientation Triage only if at least one is true:

- first entry into a major work;
- entry into a work-part with distinct method or architecture;
- learner retrieval contains isolated keywords but no work-level positioning;
- the first passage would otherwise be likely to appear unmotivated;
- a learning objective gives historical, problem-field, methodological, or formal coordinates material work-level relevance; or
- an exact Preface, Introduction, methodological self-description, or guide window provides a more appropriate ingress than Agent explanation.

Do not trigger because the work is famous, because background might be useful, or because the Agent could say more. When no foreseeable understanding risk requires a separate orientation activity, record the minimal triage basis and directly enter a verified primary window with necessary source location, source verification, and only the problem background needed for that entry. Do not manufacture an Orientation Reading Action merely because this reference exists.

## Triage record

```text
Work / work-part:
Learning objective(s) requiring orientation:
Learner currently knows:                         # diagnostic evidence; recall / hypothesis / reliable prior knowledge
Why this work appears now:
Relevant work feature(s):                         # problem field / history / method / architecture / form
Required orientation coordinates:                 # max 1–3; each has objective-relative relevance
- coordinate:
  objective relation:
  source basis / planned source mode:
  provenance expected: P | G | A
  status: diagnostic only | source-grounded | still to test
Interlocutors / background texts:                 # objective-relevant only
Orientation adequacy: SUFFICIENT | MINIMAL_ORIENTATION_NEEDED | ORIENTATION_READING_NEEDED
Deferred context:
Reconsider trigger:
```

The test is not how much context could be added, nor merely whether the learner can enter the first passage. Ask instead: **given this learning objective, learner, and work, which few coordinates must be source-grounded now so that the inquiry is not mis-specified?** A coordinate can be relevant because it frames the first passage, because it identifies the work's problem field, or because the stated objective concerns a formal or methodological feature that a first passage alone cannot establish.

## Objective-relative relevance test

For each possible historical, problem-field, methodological, or formal coordinate, record one of these results:

- `REQUIRED_FOR_WORK_ORIENTATION` — without it, the chosen learning objective would misdescribe the work, omit a relevant work feature, or invite a predictable category mistake.
- `HELPFUL_BUT_DEFERRABLE` — it may improve later interpretation but is not needed to orient the current objective; give a concrete later trigger.
- `NOT_NEEDED_NOW` — it has no material role in the current objective or entry.

`REQUIRED_FOR_WORK_ORIENTATION` is not restricted to what is logically necessary for the first primary passage. Conversely, it does not license a biography, complete intellectual history, or survey of secondary scholarship. The cap remains one to three coordinates.

## Guide decision gate

Before `GUIDE_ORIENTATION_READING`, load `references/guide-introduction.md` and apply its Guide Introduction Decision Procedure.

1. Assess the exact authorial orientation window as `SUPPORTED`, `PARTIALLY_SUPPORTED`, or `NOT_SUPPORTED` for each selected coordinate.
2. For `PARTIALLY_SUPPORTED` / `NOT_SUPPORTED`, first narrow the coordinate, split the orientation, extend adjacent primary text, or select an alternative authorial orientation window.
3. Apply the objective-relative relevance test. Do not defer a coordinate merely because the first Passage Package can be read without it.
4. `PRIMARY_ORIENTATION_READING` has priority only when its exact window performs the *same* orientation work. It does not automatically displace a bounded `COMPANION` guide whose non-duplicative contribution is material to the learning objective.
5. A `COMPANION` guide may proactively provide a structural, historical, problem-field, methodological, or formal coordinate even when the primary entrance presents no immediate comprehension difficulty. It must have documented incremental value, an exact source window, reading-cost and non-spoiling justification, P/G/A provenance, a learner reconstruction, and a return-to-primary target.
6. Do not stack sources by default. If two distinct required coordinates cannot be supported by one exact window, create two minimal orientation nodes with their own source decision, exact window, Fit Check, reconstruction, and calibration.

## Source selection

Choose the least-intrusive source action **for each selected coordinate**.

| Mode | Use when | Learner-facing output |
|---|---|---|
| `NONE` | The learner already has reliable, checkable knowledge that source-grounds every selected coordinate; no new orientation reading adds material value. | Record the checked source basis, learner reconstruction, P/G/A classification, and why new reading is unnecessary. |
| `MINIMAL_AGENT_ORIENTATION` | Only a non-substantive locator is needed, or the Agent is organizing already source-grounded learner knowledge. | At most: source-labeled locator, current entry focus, and explicitly deferred context. It cannot by itself turn an unverified learner hypothesis into a completed orientation. |
| `PRIMARY_ORIENTATION_READING` | An authorial Preface, Introduction, or methodological self-description directly supplies a selected coordinate. | Exact primary window → why it matters for the objective → one question → learner reconstruction. |
| `GUIDE_ORIENTATION_READING` | A bounded authoritative guide is the smallest source for either a still-required coordinate or an approved `COMPANION` contribution. | Exact guide window → documented incremental value → one non-spoiling question → learner reconstruction → return-to-primary target. |

Do not stack guide and primary orientation by default. Later context is Context-on-Demand unless the relevance test records it as required now.

### Contents as bounded primary orientation

An authorial table of contents may serve as `PRIMARY_ORIENTATION_READING` when the immediate need is only work-part architecture. Verify its exact PDF and printed pages, and restrict the learner-facing task to the section sequence, stated headings, page ranges, and the route into a candidate window. It does **not** establish what a section argues, the meaning of its key terms, or the warrant for a later claim; those remain for the primary-text package.

For a multi-work project with uneven local access, a readable work may receive this bounded orientation while the global domain-corpus audit remains incomplete. Defer that audit through the controlled action state rather than marking it complete, and do not treat the orientation as either project-corpus adequacy or Passage Package authorization.

If a learner gives a rich section-by-section account after reading only headings or contents, preserve it as `stored prior understanding` / `next-window preview`, not as support supplied by the orientation window. Ask for one minimal provenance split—`P`: what the headings directly establish; `H`: one body-level claim that remains to be tested—then retain the detailed account as a hypothesis or retrieval lead. This prevents a table of contents from being silently upgraded into evidence for a section’s argument.

## Orientation Reading protocol

For `PRIMARY_ORIENTATION_READING` or `GUIDE_ORIENTATION_READING`, issue only:

```text
Orientation Reading Action
Source:
Exact section/pages:
Coordinate and objective-relative relevance:
Why this matters for entering this work:
Incremental value over current knowledge / other selected source:
What to look for:
One Orientation Reading Question:
P/G/A provenance boundary:
User Orientation Reconstruction:
Return-to-primary target:
```

Then: evidence check → calibration → explicit source limit → Provisional Work Map → first Passage Package.

- Do not give a detailed Agent background summary before the learner reads.
- Do not supply a correct whole-work interpretation or answer a later primary-text question.
- `Orientation Reading ≠ Agent-summarized guide`.
- Separate `P` (primary textual support), `G` (guide framing), and `A` (Agent synthesis) during calibration.

## Question–Evidence Fit

Run Fit Check before the Orientation Reading question.

- `SUPPORTED`: the exact window can support reconstruction of its problem field, limited context, method, architecture, form, positioning, or entry relation.
- `PARTIALLY_SUPPORTED`: narrow the question or minimally extend the continuous orientation window; do not make the learner supply a missing warrant.
- `NOT_SUPPORTED`: select a different or adjacent orientation source before asking.

Orientation cannot require proof of a later primary argument, a refutation, or a settled interpretation that its source does not establish.

## Orientation Load Check and decomposition

Run this check after the source-specific Fit Check and before issuing an Orientation Reading Action.

1. Write the intended orientation as consecutive transitions, not as one broad rationale. For example: problem field → work form → selected primary entry.
2. For each transition, ask whether the exact current window directly supports it, supports only a narrower precursor, or does not support it.
3. Give the learner only the first supported transition. If later transitions lack support, mark them `unassigned` / deferred and select their source later; do not turn them into implied conclusions of the current source.
4. If a single orientation action would cross more than one unsupported transition, decompose it into minimal continuous nodes. Each node needs its own source mode, exact window, Fit Check, one question, learner reconstruction, and calibration.

**Pitfall:** Do not infer a method → topic, topic → pathway, or form → philosophical function connection merely because a Preface or guide establishes one related fact. These are separate transitions until independently supported.

## Load controls and exit

- Cap required coordinates at three. Put all other material under deferred context with a concrete later trigger.
- Ask one orientation question per source node, not a work-summary quiz.
- Keep **Work Map ≠ Passage Map**: orientation identifies goal-relative stakes and entry; Passage Pathway controls concrete nodes, bridges, anchors, conceptual step size, Bridge Load Check, and passage-level Fit Check.
- Orientation never discharges a required bridge.
- Fade first-entry support. Do not repeat whole-work orientation before every package.

Orientation may exit only when the learner can:

1. state the selected work-level coordinates and how each serves the present learning objective;
2. identify the source basis and provenance for each coordinate (`P`, `G`, or clearly labeled `A`), including any reliable prior knowledge accepted without new reading;
3. distinguish a source-grounded coordinate from a still-open interpretive or predictive hypothesis;
4. distinguish why the first primary window is a sensible **candidate** entry from what the learner has actually learned from that unread window; and
5. state, or explicitly adopt from their already expressed unresolved question, one question to carry into that window.

Condition 4 is a route-awareness check, not a demand for pre-reading textual knowledge. Ground the entry rationale in the verified Selection Record and the selected orientation coordinates; do not ask the learner to assert, paraphrase, or provide evidence for content they have not read. If the learner says that a proposed characterization of the window is only tentative because they have not read it, preserve that boundary as correct evidence discipline. A learner's paraphrase of an Agent hint, or a pre-reading prediction that has not been independently sourced, satisfies only diagnostic readiness for claims about the primary text; it cannot replace source-grounded orientation. No new orientation reading is required if existing, reliable, checkable learner knowledge already satisfies all selected coordinates; record that basis and do not manufacture background work.

### Multi-node synthesis before Exit

When orientation uses two or more source nodes, completing and calibrating every individual node is necessary but not by itself an Exit. Before deciding Exit, issue one **no-new-reading `ORIENTATION_EXIT_RECONSTRUCTION`** that requires the learner to:

1. name each selected coordinate and its objective-relative role;
2. identify the exact source and P/G/A provenance for each coordinate;
3. distinguish what each source establishes from what it merely makes necessary to examine;
4. name the hypotheses or questions reserved for primary-text testing; and
5. distinguish the verified, Agent-side Selection Record for the proposed first window from learner knowledge of that unread window, then explain how the selected coordinates make it a proportionate next test.

Do not make item 5 a disguised primary-text quiz: the learner may say that the exact contents remain unread and tentative. In that case, preserve the statement as a boundary rather than treating it as a failure; the Selection Record supplies the text-specific rationale, while the learner confirms the route and carries an open question into the reading. Calibrate this synthesis before Exit. The synthesis is an evidence-bound integration check, not a new source reading and not an invitation to turn guide coordinates into a whole-work interpretation. If it exposes a real coordinate gap, select only the smallest additional orientation node; otherwise do not add background merely to prolong orientation.

### Scope-of-evidence discipline

An orientation window licenses only the propositions it actually identifies or supports. Do not use a source's general characterization of a corpus, genre, or authorship practice to assert that a particular work belongs to that class unless the window names the work or an independently checked bibliographical source establishes the link. Likewise, do not convert a characterization of a whole corpus into a claim that every component is necessary for understanding the whole. Record such moves as hypotheses or verify them separately.

It does not require biography, complete intellectual history, all interlocutors, whole-work summary, settled interpretation, or proof of later claims. During triage, the Agent may locate and record candidate primary windows, but a candidate is not a learner-facing assignment. When triage concludes `ORIENTATION_READING_NEEDED`, do not set an active Passage Package, mark package corpus `SUFFICIENT_FOR_NOW`, or issue a Passage Package Reading Action until the applicable Exit is met. When no distinct orientation is needed, a verified direct primary entry may proceed without manufacturing an orientation course. After an orientation Exit, activate only the selected first package and issue its Reading Action; record unused material as deferred context with a concrete later trigger.

## Regression cases

### Concept-shift exploratory rereading

For the objective “investigate how a concept's meaning shifts across a work, and whether a short piece of writing can test that shift,” the pre-reading claim that the concept is not merely repeated but altered is a useful **Orientation Diagnostic**. It does not by itself complete Work-Level Orientation: it identifies a semantic pressure, but does not source-ground the work's problem field or the formal coordinate relevant to the writing objective.

A compliant finite orientation may select, after exact-window verification:

1. one bounded encyclopaedia or verified scholarly orientation window for the relevant problem-field / authorship coordinate; and
2. one verified form-focused companion window for the form coordinate, if it makes a non-duplicative, non-spoiling contribution to the stated writing objective.

The task must record exact pages or section before issuance, P/G/A provenance, incremental value, one learner reconstruction per node, and a return-to-primary target. It must not assign the complete articles, convert the guides into an Agent summary, or disclose the opening passage's answer. Under this regression, the old exit—Agent cue about the concept being altered, followed by learner restatement—fails at conditions 1–3 above. The new procedure may select the two bounded nodes, or fewer if a verified exact primary or existing reliable learner source covers one coordinate.

### No-extra-background counterexample

Suppose the objective is limited semantic close reading of a short, self-presenting text; the learner already has reliable, checkable knowledge of its immediate problem and method; and neither historical context nor form bears materially on that objective. Record the source basis, classify those coordinates `NOT_NEEDED_NOW`, and use `NONE` or a minimal primary orientation. Do not require a biography, companion guide, or background survey simply because Work Orientation exists.

## State and recovery

In `learning-state.md`, record only:

```text
## Work Orientation
Work:
Learning objective(s):
Triage result / diagnostic readiness:
Required coordinates and objective relation:
Orientation source decision:
Exact source window / checked existing source:
P/G/A provenance:
User orientation reconstruction:
Open hypotheses still to test:
Orientation status: not_needed | in_progress | sufficient_for_entry
Deferred context:
- item:
- trigger:
```

On recovery, do not repeat an orientation marked `sufficient_for_entry`. Restore the recorded coordinates, source bases, provenance, hypotheses, and deferred-context triggers, then proceed with the active Passage Pathway.

If review shows that a Passage Package was activated or issued before Orientation Exit, reopen orientation through the recorded plan and the Orientation Exit procedure. Preserve the already-located primary window as a candidate only; agent-side verification is not learner completion.

### Reopening a prematurely activated package

This repair is a manual evidence-and-plan correction, not a state-file operation. Keep the conflict and the proposed correction in plain Markdown; do not hand-edit project state to imitate a transition.

Use this repair after a workflow update, a recovery audit, or a user challenge reveals that the Orientation Exit was never completed.

1. Write down the current active package, the missing orientation evidence, and the exact learner artefacts that exist; do not infer completion from a note that merely names a window.
2. Add or select the minimal orientation node and make its orientation action the current next action **before** deferring the premature action; an active action cannot be deferred.
3. Defer the premature action and its pathway node, then set the orientation triage to `ORIENTATION_READING_NEEDED`.
4. Block the old package and clear it from the active route. Record explicitly that no active package is selected, rather than leaving a stale package name in the plan.
5. Update the candidate Scope Card to `BLOCKED` / unissued, retain its primary window and its reconsider triggers, and mark any language bridge or agent-side text location as support only—not learner reading.
6. Re-read the written plan against the learner records before issuing anything. Only issue the Orientation Diagnostic; do not reissue the candidate package until Orientation Exit is source-grounded.

Do not repair canonical state by direct file edits, because the mirrors and transition history would then disagree.
