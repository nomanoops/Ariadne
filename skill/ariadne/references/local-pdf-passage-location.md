# 本地 PDF 的 Passage Package 定位

用于用户提供的、已经确认文本层可读（`usable` 或 `degraded_but_usable`）的 PDF。目标是手工或半手工地定位可供人工判定的连续原文窗口，而不是自动解释文本。本核心不附带文本层检查脚本；判定必须来自实际打开文件后的观察，并记录所用阅读器或解析方式。

## 程序

1. **先确认文本层状态。** 在本地 PDF 阅读器中打开文件，尝试选择、复制并搜索一小段正文。

   - 能稳定选中、搜索并对应到页面 → `usable`。
   - 能选中但字符错乱、断行或偶有缺字 → `degraded_but_usable`；关键引文仍须页面视觉核验。
   - 无法选中、复制为空或明显只是扫描图像 → `ocr_required`，转入 Manual OCR Rule，不得继续本程序。

   若一个提取器报告“无可提取文本”而另一个阅读器可以选中文字，不要仅据前者降级为 `ocr_required`；以**窄范围**的页面视觉核验（题名页、目录或当前关键词页）确认。不同提取器对同一嵌入文本层的兼容性并不相同。

2. **用少量明确关键词定位。** 关键词应来自当前未决 hinge：术语、章节名、已知人名或连续段落的起始短语。不要用几十个宽泛词扫整本书，也不要用关键词频次推断重要性。

3. **持久化候选位置，而不是依赖一次搜索回显。** 记录每个命中所在的 PDF 页码与可见的印刷页码；随后读取该页、前一页和后一页，确认章节标题、连续论证与页码对应。不要把被截断的搜索结果当作定位证据。

4. **处理抽取噪声。** 若阅读器把章节号或标题拆成字符、换行或重复文本，可以仅为**候选生成**而忽略空白和换行后再匹配；不得据此生成引文或改写原文。每个候选边界都必须回到实际页面核验。

5. **选出最小连续窗口。** 从已核验的候选页只选取能承担当前一个局部问题的最小连续窗口；检查其前后相邻页是否提供 Required Bridge 或 Exit Bridge。若用户指定节段的最近前文已经明确提出本包问题，可将它记录为较窄的 Required Bridge，而不要因章节编号自动扩大到整段更早的背景。

   若相邻章节／小节共用同一 PDF 页，按**视觉可见的下一标题或末句**界定精确终点，而不是把整页自动纳入或排除。阅读指令必须写明“读至下一标题之前”或给出末句；否则页码边界会把下一论证动作混入当前 Package。

6. **重做 Question–Evidence Fit。** 在发出 Guided Text Entry 前，对精确的 question–window pair 重做 QEF。关键词命中只表示候选位置，不表示该页已经支持更强的推论。

7. **窄范围视觉核验。** 对将承担论证作用的原文措辞、页码和起止位置，只查看已定位的少量页面，核对标题、印刷页码、关键措辞，以及所选范围是否确实在预期的论证边界开始或结束。可用 `vision_analyze` 或阅读器自身的页面视图。视觉检查只验证文本定位之后的精确证据；它不替代文本阅读，也不构成 OCR workflow。

8. **记录。** 只有在文本定位与视觉核对一致后，才把精确 page window 及其 Bridge / Anchor / Exit 角色写入 Scope Card 与 Text Map。若两者不一致，以视觉页面为准核验措辞，并在发出 Reading Action 前重查候选边界。

## 边界

- 不对 `ocr_required` PDF 使用此法作为变相 OCR。
- 不让关键词频次、单页命中或自动截取替代章节结构、Passage Package 的 Bridge Load Check 或文本证据判断。
- 用户提供的项目内材料按 `local user-provided copy` 处理；不要从文件名推断或记录历史获取来源。
- 平台声明仅覆盖 macOS：本核心只在 macOS 上被静态审阅过，未在其他系统验证阅读器行为。
